## 真实浏览器与服务重启

使用独立测试浏览器、临时数据目录和合成数据，不依赖用户的真实浏览器内容。

1. 从页面注册账号 A，检测到测试浏览器的 1 个画布、1 项素材、1 张图片、1 个导演台工程及渠道配置。
2. 用户确认后完成迁移；服务端能读取相应文档和 68 字节测试 PNG，原浏览器配置仍保留，完成标记仅在服务端提交后出现。
3. 迁移后通过 UI 新建画布，服务端项目数变为 2，排除了恢复后旧回调失效的问题。
4. 在画布中新建导演台节点，修改工程名称并立即关闭面板；关闭完成后，服务端已有对应工程和版本号。
5. 从页面退出 A、注册 B 并跳过迁移；B 的服务端文档和媒体数均为 0，不能读取 A 的画布。
6. 重启生产预览进程，使用同一数据目录；B 的现有会话仍有效。
7. 在没有旧画布 localStorage 的另一个独立浏览器中登录 A，恢复 2 个画布、2 份导演台文档，并成功解码服务端测试图片（naturalWidth = 1）。
8. 最终浏览器控制台无错误。保存状态放在顶栏，不遮挡资产卡片按钮。
9. 在开发模式下直接请求数据目录的数据库、密钥、`?raw` 和 `/@fs` 路径均被拒绝；未登录的业务 API 返回 401。

## 审查后修复的关键问题

- 导入 ZIP 在读取前捕获账号及会话，逐次上传校验；新的媒体键防止覆盖旧文件。
- 401 时按账号保留本标签页内存草稿；旧 flush 不再假成功，恢复草稿保留原始冲突基线。
- 恢复数据协调重新加载账号；账号 epoch 防止旧 UI 回调写入新账号。
- 路由跳转、账号退出和导演台关闭均等待保存确认；失败不直接卸载编辑器。
- 导演台启动期间监听账号变化并重新核验会话；工程恢复文件包含尚未保存的姿势库。
- 服务器私有目录不能位于静态输出中，相关符号链接检查失败时不静默放行。
- 图片/媒体异步操作绑定启动它的账号；视频上传失败不再把临时 URL 当作持久化成功。

## 环境限制与运维注意

- 本机没有 Docker，已提供 Dockerfile / Compose / 命名卷配置，未声称完成容器构建和运行验证。
- 没有执行真实 ChatGPT OAuth 或付费生图。Codex 接口的自动测试使用模拟客户端。
- Codex CLI 和自定义脚本只适用于可信用户；用户目录和 API 所属关系不是操作系统级的不可信租户隔离。
- 草稿恢复仅在当前标签页内存中，刷新/关闭前须确认保存或导出。
- 备份必须同时包含数据库、加密密钥、媒体和各用户 Codex home；不要只复制 SQLite 主文件或删除 Compose 数据卷。
