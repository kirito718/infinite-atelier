# 账号与持久化方案完成性审计

目标：把已确认的账号 / SQLite / 媒体持久化方案全部做完，并用与要求相匹配的证据完成测试和验收。此记录补充首次仅完成原生 Node 验证的报告，不把“Docker 配置存在”当作容器验收完成。

## 边界

依据 `specs/2026-09-08-accounts-persistence-design.md` 和 `plans/2026-09-08-accounts-persistence.md`。原方案不自动连接真实 ChatGPT 账号、不调用付费模型、不修改/发布已有远程服务，不包含多人协作、多副本数据库和邮件找回。本轮没有缩减这些已确认的功能要求，也没有把模拟 Docker 当作真实容器。

## 浏览器备份恢复证据

在上述真实镜像的独立测试账号中，放入画布、图片/文本素材、生成历史、提示词封面、渠道配置、导演台工程和非空姿势库，以及 PNG/WAV 文件。通过界面导出备份，实际 ZIP 包含全部 7 类文档和 2 个字节一致的媒体文件。随后将 7 类文档改空/改名，再通过文件选择器和确认对话框恢复：

- 原画布、素材文字、历史、配置、封面、导演台及姿势恢复。
- 新媒体键在画布、素材、历史及导演台引用之间保持一致，内容哈希仍与备份相同。
- 原媒体未被覆盖，服务器文件总数由 2 变为 4。
- 不刷新窗口也能通过 UI 新建画布，排除了恢复后旧绑定失效。
- 从服务器解码图片成功，浏览器控制台无错误。

证据位于 `web/output/ct/browser/backup-export-evidence.json`、`backup-restore-evidence.json` 及 `web/output/playwright/container/restored-assets.png`。这些是合成测试数据，不包含用户实际内容。
